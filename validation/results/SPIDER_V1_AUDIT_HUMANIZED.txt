1. Executive Summary and Verification Scope
We audited the CogniCore Spider V1 benchmark evaluation using offline logs. All tables and counts in this report come from append-only evaluation records (validation/raw/spider/spider-main-v1_units.jsonl) and pre-run gold checks (validation/data/spider/gold_checks.jsonl). Prompt cache files (validation/raw/spider/llm_cache.jsonl) provided verification for model inputs. No language model was queried during the audit; every metric reflects raw disk data.

Key Audit Findings
1. Pre-Inspection Freezing of Sample B: In line with preregistered protocol, an independent hold-out sample of 300 questions (frozen_sample_300_B.jsonl) was drawn from unused positions in pool_order.json. This sample satisfied all registered eligibility constraints. Amendment SPIDER-B1 (git tag: spider-sample-b-frozen) locked the file before anyone checked individual results in Sample A. Overlap between Sample B and earlier pools (Pilot, Candidates, Sample A) was zero.

2. Three-Way Performance Breakdown:
- Baseline C0: 191 correct (63.7%), 94 wrong executions (31.3%), 15 abstentions (5.0%). Selective accuracy was 67.0% (191 / 285).
- Governed Variant C4nr: 180 correct (60.0%), 112 wrong executions (37.3%), 8 abstentions (2.7%). Selective accuracy reached 61.6% (180 / 292).
- Full Governed Pipeline C4: 180 correct (60.0%), 114 wrong executions (38.0%), 6 abstentions (2.0%). Selective accuracy stood at 61.2% (180 / 294).

3. Primary Endpoint Outcome: McNemar's exact two-sided test on the 33 discordant pairs (11 C4 wins versus 22 C0 wins) produced p = 0.0801. That outcome corresponds to a net difference of -3.7%. A 10,000-replicate cluster bootstrap gave a 95% confidence interval of [-11.3%, +2.4%]. Because this interval spans zero, the null hypothesis stands.

4. Rectification of Four Published Claims: SPIDER_V1_FINAL_REPORT.md contained four statements that conflicted with raw records:
- Claim 1: A reported "+1 in 18 of 19 databases" gain was an arithmetic sign error (169 minus 172 equals -3).
- Claim 2: The assertion of "zero schema hallucinations" was incorrect. C4 hallucinated non-existent columns in course_teach and student_transcripts_tracking. Similar column errors appeared in car_1 and concert_singer.
- Claim 3: The claimed "54% fewer exceptions" conflated handled SQL execution errors with crashes. Both C0 and C4 ran with zero unhandled crashes.
- Claim 4: The 232 ms latency reported for C4 reflected in-memory cache hits from C4nr. True uncached latency averaged 4.4 to 7.0 seconds.

8. Rectification of Inaccurate Report Statements (Part G)
This section reconciles four unsupported statements from SPIDER_V1_FINAL_REPORT.md against raw logs. The original report file remains unchanged in the archive.

Discrepancy 1: Database Delta Direction
Section 8 reported: "Outside of flight_2, (C4 - C0) was +1 across the remaining 18 databases (169 vs. 172)."
Audit finding: This was an arithmetic sign error. Across those 18 databases, C0 answered 172 queries correctly and C4 answered 169. Subtracting 172 from 169 yields -3, not +1.
Corrected statement: "Across the 18 databases outside of flight_2, C4 trailed C0 by -3 items (169 vs. 172). Positive net deltas appeared in three databases: world_1 (+3), car_1 (+2), and wta_1 (+1). Performance matched C0 across eight databases. C4 trailed C0 in the remaining eight schemas: orchestra (-2), student_transcripts_tracking (-2), dog_kennels (-1), tvshow (-1), concert_singer (-1), employee_hire_evaluation (-1), network_1 (-1), and flight_2 (-8)."

Discrepancy 2: Schema Column Hallucinations
Section 14 stated: "Zero schema hallucinations on foreign keys in complex schemas (car_1, world_1)."
Audit finding: Raw logs refute this claim. C4 hallucinated non-existent columns in course_teach (spider-dev-402, T2.Course_ID) and student_transcripts_tracking (spider-dev-529, semester_name). Similar errors occurred on spider-dev-167 in car_1 (T1.Horsepower). In concert_singer (spider-dev-37), C4 hallucinated a direct join between concert and singer. That join bypassed the junction table entirely.
Corrected statement: "The governance engine reduced foreign-key navigation errors on selected multi-table schemas, such as car_1. It did not eliminate column or join hallucinations across the benchmark. Unresolvable column reference errors occurred across several queries."

Discrepancy 3: Runtime Exceptions Reduction
Section 14 reported: "54% reduction in unhandled runtime database exceptions (13 down to 6)."
Audit finding: This statement conflated caught query errors with unhandled crashes. Neither pipeline crashed. All errors were caught inside application try-catch blocks. What dropped was queries throwing execution errors reaching final output (13 in C0 down to 6 in C4, an observed reduction of 53.8%). This reduction did not improve overall accuracy because repaired queries selected non-gold rows.
Corrected statement: "The governance pipeline reduced SQL query execution errors that reached final output from 13 in C0 to 6 in C4 (a 53.8% reduction). This error suppression did not raise overall accuracy. Modified queries frequently returned row tuples that differed from gold answers."

Discrepancy 4: C4 Execution Latency
Sections 4 and 11 reported: "C4: Mean 232 ms (cached initial queries) | P50 38 ms | P95 114 ms."
Audit finding: Presenting 232 ms as C4 execution latency gave the appearance of a tenfold speed improvement over C0 (3,871 ms). In reality, C4 ran after C4nr with in-memory completion caching active, where the cache hit rate reached 98%.
Corrected statement: "True uncached execution latency for C4 averages approximately 4,380 ms. Multi-turn recovery introduces an additional 2,400 ms per correction turn. The reported 232 ms average reflected in-memory cache reuse from the prior C4nr execution."
